# v2 — Internationalisation (IT / EN / FR)

## Contexte

Ajout du support multilingue sur le template restaurant et le plugin de réservation.
- **Langue principale :** 🇮🇹 Italiano
- **Langues secondaires :** 🇬🇧 English, 🇫🇷 Français
- **Structure d'URL :** sous-répertoires (`/en/`, `/fr/`, racine = italien)
- **Plugin utilisé :** Polylang 3.8.4 (gratuit, open source)

---

## Concepts clés

### Système GNU Gettext (WordPress i18n natif)

WordPress utilise le système GNU Gettext pour les chaînes statiques du code.

| Fichier | Rôle |
|---|---|
| `.pot` | Template (catalogue de toutes les chaînes traduisibles extraites du code) |
| `.po` | Traductions lisibles par l'humain (`msgid` → `msgstr`) |
| `.mo` | Binaire compilé depuis le `.po` — **c'est ce que WordPress charge** |

Nommage : `{text-domain}-{locale}.mo` → `restaurant-theme-it_IT.mo`

Les fonctions de traduction dans le code :
```php
__( 'Chaîne', 'text-domain' )          // retourne la traduction
_e( 'Chaîne', 'text-domain' )          // echo la traduction
esc_html__( 'Chaîne', 'text-domain' )  // retourne + échappe le HTML
esc_html_e( 'Chaîne', 'text-domain' )  // echo + échappe le HTML
```

**Parallèle Symfony :** équivalent à `$translator->trans('key', [], null, $locale)` + fichiers `translations/messages.it.yaml`.

### Polylang (traduction du contenu)

Polylang gère la traduction des **contenus** (pages, articles, CPT) et la structure d'URL multilingue. Il s'appuie sur le système natif WP pour les chaînes du code.

```
monsite.com/          → Italiano (langue par défaut, /it/ masqué)
monsite.com/en/       → English
monsite.com/fr/       → Français
monsite.com/en/menu   → page "Menu" en anglais
monsite.com/fr/menu   → page "Menu" en français
```

**Parallèle Symfony :** équivalent au composant `LocaleSwitcher` de Symfony UX + la configuration `framework.translator.default_locale`.

Les containers existants suffisent. Polylang est installé dans le volume WordPress nommé (pas un bind mount — c'est un plugin tiers, pas notre code).

## Outils installés

### Polylang (plugin WordPress)
```bash
# Installé via WP-CLI dans le container Docker
docker exec wordpress-wordpress-1 bash -c \
  "php wp-cli.phar plugin install polylang --activate --allow-root"
```

### WP-CLI i18n (génération des .pot)
```bash
# Génère le .pot en scannant tous les appels __() / _e() / esc_html_e() etc.
php wp-cli.phar i18n make-pot /chemin/vers/theme  /chemin/vers/languages/theme.pot
php wp-cli.phar i18n make-pot /chemin/vers/plugin /chemin/vers/languages/plugin.pot

# Compile les .po en .mo
php wp-cli.phar i18n make-mo /chemin/vers/languages/
```

### `wp-content/plugins/restaurant-reservation/includes/class-reservation-cpt.php`

const META_LANG = '_res_lang';  // Langue du visiteur au moment de la soumission

```php

```

**3. Stockage de la langue à la création de la réservation :**
```php
// pll_current_language() = slug Polylang ('it', 'en', 'fr')

```

**4. Retour de la langue dans `get()` :**
```php
'lang' => get_post_meta( $post_id, self::META_LANG, true ) ?: 'it',
```

### `wp-content/plugins/restaurant-reservation/includes/class-reservation-email.php`

Sélection du template d'email selon la langue de la réservation :

```php
$lang         = $reservation['lang'] ?? 'it';
$action_key   = $is_accepted ? 'accepted' : 'rejected';
$subject_key  = "subject_{$action_key}_{$lang}";   // ex: subject_accepted_en
$template_key = "email_{$action_key}_{$lang}";      // ex: email_accepted_en

// Fallback vers IT si la langue n'a pas de template configuré
$subject  = $settings[$subject_key]  ?? $settings["subject_{$action_key}_it"]  ?? '';
$template = $settings[$template_key] ?? $settings["email_{$action_key}_it"]    ?? '';
```

Les clés de settings suivent le pattern `{type}_{statut}_{langue}` :
- `subject_accepted_it`, `email_accepted_it`
- `subject_accepted_en`, `email_accepted_en`
- `subject_accepted_fr`, `email_accepted_fr`
- `subject_rejected_it`, `email_rejected_it`
- etc.

## Configuration Polylang (effectuée via WP-CLI)

```php
// 3 langues créées
$model->add_language([ 'name' => 'Italiano', 'slug' => 'it', 'locale' => 'it_IT', ... ]);
$model->add_language([ 'name' => 'English',  'slug' => 'en', 'locale' => 'en_US', ... ]);
$model->add_language([ 'name' => 'Français', 'slug' => 'fr', 'locale' => 'fr_FR', ... ]);

// Configuration des options Polylang
$options['default_lang'] = 'it';  // Langue par défaut
$options['rewrite']      = 1;     // Sous-répertoires activés
$options['hide_default'] = 1;     // /it/ masqué → URL propre à la racine
$options['force_lang']   = 1;     // Mode : sous-répertoires (pas sous-domaines)
```

Structure d'URL résultante :
```
monsite.com/          → Italiano  (/it/ masqué)
monsite.com/en/...    → English
monsite.com/fr/...    → Français
```

## Étapes de finalisation dans WP Admin

```
1. Langue du site       → Réglages > Général > Langue du site : Italiano
2. Vérifier Polylang    → Langues > Réglages — confirmer les slugs /en/ /fr/
3. Traduire les pages   → Chaque page a un bouton "+" par langue dans l'éditeur
4. Traduire les plats   → Carte > chaque plat → ajouter version EN et FR
5. Templates email      → Réservations > Configuration
                           Onglet 🇮🇹 → remplir subject/body IT
                           Onglet 🇬🇧 → remplir subject/body EN
                           Onglet 🇫🇷 → remplir subject/body FR
6. Menu multilingue     → Apparence > Menus → créer un menu par langue
                          (Polylang ajoute un filtre de langue dans l'interface)
7. Tester               → Visiter /en/ et /fr/ — vérifier le sélecteur de langue
                          Soumettre une réservation en EN → email en anglais
                          Soumettre une réservation en FR → email en français
```

Ciao {{client_prenom}},

A presto,
{{restaurant_nom}}

del {{reservation_date}} alle {{reservation_heure}}.

Cordiali saluti,
{{restaurant_nom}}
