# v3 — Notification email admin lors d'une nouvelle réservation

## Contexte

Quand un client soumet le formulaire de réservation, l'administrateur reçoit immédiatement un email récapitulatif avec :
- Toutes les informations du client (nom, prénom, email, téléphone, date, heure, couverts, message)
- La langue dans laquelle la réservation a été faite (🇮🇹 / 🇬🇧 / 🇫🇷)
- Un bouton CTA qui pointe directement vers la page de détail dans le backoffice

---

## Architecture

Le système repose sur l'**événement custom `reservation_created`** déjà déclenché dans `Reservation_CPT::create()` :

```
Client soumet formulaire
        ↓
Reservation_Form::handle_ajax()
        ↓
Reservation_CPT::create() → do_action('reservation_created', $post_id)
        ↓
Reservation_Email::send_admin_notification($post_id)  ← NEW
        ↓
wp_mail() → Mailpit (dev) / SMTP (prod)
```

**Parallèle Symfony :** `do_action('reservation_created')` ≈ `$dispatcher->dispatch(new ReservationCreatedEvent($id))`. Le listener est enregistré dans le bootstrap du plugin, le découplage est total.

## Fichiers modifiés

### `wp-content/plugins/restaurant-reservation/restaurant-reservation.php`

**1. Hook dans `register_hooks()` :**
```php
add_action( 'reservation_created', [ $email, 'send_admin_notification' ] );
```

**2. Option par défaut dans `register_activation_hook` :**
```php
'notify_email' => get_bloginfo( 'admin_email' ),
```

L'option est initialisée à l'activation du plugin avec l'email admin WordPress. Modifiable ensuite depuis Réservations > Configuration.

---

### `wp-content/plugins/restaurant-reservation/includes/class-reservation-email.php`

**1. Nouvelle méthode publique `send_admin_notification(int $post_id)`**

Listener de `reservation_created` :
- Récupère les données de la réservation via `Reservation_CPT::get()`
- Lit `notify_email` dans les settings (fallback : `get_bloginfo('admin_email')`)
- Valide que `notify_email` est bien une adresse email (`is_email()`)
- Construit l'URL de détail avec `add_query_arg()` :
  ```php
  add_query_arg([
      'page'           => 'restaurant-reservations',
      'action'         => 'view',
      'reservation_id' => $post_id,
  ], admin_url('admin.php'))
  ```
- Construit un sujet clair : `"🍽️ Nouvelle réservation — Prénom Nom le DD/MM/YYYY"`
- Appelle `build_admin_notification_html()` puis `send()`

**2. Nouvelle méthode privée `build_admin_notification_html(array $r, string $detail_url, string $lang_label)`**

Génère un email HTML complet et responsive :
- En-tête coloré avec la couleur principale du thème (`get_theme_mod('color_primary', '#c8a96e')`)
- Tableau récapitulatif (Client, Email, Téléphone, Date, Heure, Couverts, Langue, Message)
- Bouton CTA "✓ Traiter cette réservation" → lien direct vers la page de détail admin
- Lien de fallback en texte brut sous le bouton
- Pied de page avec le nom du restaurant

**3. Correction dans `send()` :**

`build_admin_notification_html()` retourne un document HTML complet (`<!DOCTYPE html>`). La méthode `send()` ne doit pas l'échapper ni l'envelopper une seconde fois. Détection ajoutée :
```php
if ( $is_html && ! str_contains( $body, '<!DOCTYPE' ) ) {
    $body = nl2br( esc_html( $body ) );
    $body = $this->wrap_html( $body, get_bloginfo( 'name' ) );
}
```
Les templates clients (texte brut saisi en admin) continuent d'être wrappés normalement.

### `wp-content/plugins/restaurant-reservation/includes/class-reservation-admin.php`

**1. Nouveau champ `notify_email` dans la Settings API :**
```php
$this->add_settings_text_field(
    'notify_email',
    __( 'Email de notification (admin)', 'restaurant-reservation' ),
    'restaurant_res_sender_section',
    'email'
);
```
Le champ apparaît dans l'onglet 🇮🇹 de Réservations > Configuration, dans la section "Expéditeur des emails".

**2. Sanitisation dans `sanitize_settings()` :**
```php
$sanitized['notify_email'] = sanitize_email( $input['notify_email'] ?? '' );
```

## Configuration dans WP Admin

```
Réservations > Configuration > onglet 🇮🇹 Italiano
Section "Expéditeur des emails"
→ Champ "Email de notification (admin)" : entrer votre email personnel
```

Valeur par défaut : email administrateur WordPress (`get_bloginfo('admin_email')`).

## Test en développement

1. Vérifier que Mailpit tourne : `http://localhost:8025`
2. Soumettre une réservation via le formulaire frontend
3. Mailpit reçoit l'email admin : tableau récapitulatif + bouton CTA

5. Accepter ou refuser → email client envoyé dans la langue de la réservation (cf. v2)

## Variables de template disponibles pour l'email admin

L'email admin utilise un template HTML codé en dur (non modifiable via l'admin), car il est destiné à un usage interne et doit toujours afficher toutes les informations.

Les emails clients (acceptation/refus) restent configurables via les templates en v2.
