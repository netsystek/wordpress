## 2. Plugin de réservation — Configuration

Accessible via **Admin > Réservations > Configuration**.

### Capacité & Jours d'ouverture

| Réglage | Description |
|---|---|
| **Confirmation automatique** | Si coché : la réservation est immédiatement acceptée et un email de confirmation est envoyé au client sans aucune action de l'administrateur. |
| **Nombre maximum de couverts** | Limite le select "Couverts" dans le formulaire public. Validé également côté serveur. Défaut : `20`. |
| **Jours de fermeture** | Cases à cocher (Lundi → Dimanche). Les clients ne peuvent pas sélectionner ces jours. Validé côté client (JS) et côté serveur (PHP). |

### Labels du formulaire de réservation

Tous les textes visibles dans le formulaire public sont personnalisables :

| Réglage | Valeur par défaut |
|---|---|
| `label_prenom` | `Prénom` |
| `label_nom` | `Nom` |
| `label_email` | `Email` |
| `label_telephone` | `Téléphone` |
| `label_date` | `Date` |
| `label_heure` | `Heure` |
| `label_personnes` | `Couverts` |
| `label_message` | `Message (optionnel)` |
| `label_placeholder` | `Allergies, occasion spéciale, demandes particulières…` |
| `label_required` | `* Champs obligatoires` |
| `label_submit` | `Demander une réservation` |

### Expéditeur des emails

| Réglage | Description |
|---|---|
| `sender_name` | Nom affiché dans le champ "De :" des emails |
| `sender_email` | Adresse email de l'expéditeur |
| `notify_email` | Adresse qui reçoit les notifications de nouvelles réservations |

### Templates email

Deux templates à configurer (variables disponibles listées en bas de la page de configuration) :

| Template | Clés |
|---|---|
| Email de confirmation (client accepté) | `subject_accepted`, `email_accepted` |
| Email de refus | `subject_rejected`, `email_rejected` |

**Variables disponibles dans les templates :**

| Variable | Description |
|---|---|
| `{{client_prenom}}` | Prénom du client |
| `{{client_nom}}` | Nom du client |
| `{{client_email}}` | Email du client |

| `{{reservation_heure}}` | Heure de la réservation |
| `{{reservation_personnes}}` | Nombre de couverts |

## 3. Flux de réservation

### Avec confirmation automatique activée
```
Client soumet le formulaire
  → Validation JS (champs requis, jour de fermeture)
  → Requête AJAX vers admin-ajax.php
  → Validation PHP (champs, email, date, jour fermé, max couverts)
  → Création de la réservation (statut : Acceptée)
  → Email de confirmation envoyé au client
  → Email de notification envoyé à l'admin
  → Message de succès affiché au client
```

### Sans confirmation automatique (validation manuelle)
```
Client soumet le formulaire
  → Validation JS + PHP
  → Création de la réservation (statut : En attente)
  → Email de notification envoyé à l'admin
  → Message "Demande reçue, confirmation à venir" affiché au client

Admin reçoit l'email → clique le lien → page de détail
  → Clic "Accepter" ou "Refuser"
  → Statut mis à jour
  → Email de confirmation ou refus envoyé au client
```

## 4. Suppression du support multilingue (Polylang)

Cette version supprime intégralement le support i18n ajouté en V2 :

- Suppression des fichiers `.po` / `.mo` / `.pot`
- Suppression de `load_theme_textdomain()` et `load_plugin_textdomain()`
- Suppression du sélecteur de langue Polylang dans le header
- Remplacement de tous les appels `__()`, `esc_html_e()`, `esc_attr_e()` par des chaînes en dur
- Suppression des templates email multilingues (IT/EN/FR) → un seul template par action
- Suppression du champ `META_LANG` dans les réservations
