# v1 — Template WordPress Restaurant + Plugin de Réservation

## Contexte

Création from scratch d'un **thème WordPress restaurant one-page** entièrement configurable depuis l'admin, suivie d'un **plugin de réservation de table** avec backoffice complet et emails automatiques.

Objectif pédagogique : apprendre WordPress en autonomie avec des parallèles constants vers PHP/Symfony.

---

## Environnement

- **WordPress** : `http://localhost:8080`
- **Mailpit** (capture emails dev) : `http://localhost:8025`
- **Stack** : Docker Compose — WordPress + MySQL 8.0 + Mailpit
- **Commandes** : `make up` / `make down`

## Phase 2 — Plugin `restaurant-reservation`

### Structure créée

```
wp-content/plugins/restaurant-reservation/
├── restaurant-reservation.php         # Bootstrap, hooks, activation/désactivation
├── includes/
│   ├── class-reservation-cpt.php      # CPT "reservation" + statuts + méthodes CRUD
│   ├── class-reservation-form.php     # Shortcode + traitement AJAX (nonce sécurisé)
│   ├── class-reservation-email.php    # wp_mail() + templates avec variables
│   └── class-reservation-admin.php   # Menus admin + Settings API
├── admin/
│   ├── class-list-table.php           # Étend WP_List_Table (liste paginée + filtres)
│   ├── assets/
│   │   ├── css/admin.css              # Badges statut, grille détail
│   │   └── js/admin.js                # AJAX changement de statut
│   └── views/
│       ├── list-reservations.php      # Vue : liste des réservations
│       ├── reservation-detail.php     # Vue : détail + boutons action
│       └── settings.php               # Vue : configuration + test email
└── public/
    ├── assets/
    │   ├── css/form.css               # Styles du formulaire frontend
    │   └── js/form.js                 # Soumission AJAX (fetch API)
    └── views/reservation-form.php     # HTML du formulaire
```

### Fonctionnalités du plugin

**Formulaire frontend** (shortcode `[restaurant_reservation]`) :
- Champs : Prénom, Nom, Email, Téléphone, Date, Heure (créneaux 12h–22h30), Couverts (1–20), Message
- Validation côté serveur + côté client
- Nonce anti-CSRF (`wp_create_nonce` / `check_ajax_referer`)
- Soumission via `fetch()` sans rechargement de page
- Date minimum = demain (attribut HTML `min`)

**Stockage** (Custom Post Type `reservation`) :
- Statuts : `res_pending` (En attente) / `res_accepted` (Acceptée) / `res_rejected` (Refusée)
- Métadonnées : `_res_prenom`, `_res_nom`, `_res_email`, `_res_telephone`, `_res_date`, `_res_heure`, `_res_personnes`, `_res_message`

**Backoffice** (WP Admin > Réservations) :
- Liste paginée avec filtres par statut et recherche (nom, email, téléphone)
- Tri par colonnes (date, statut)
- Actions groupées (accepter / refuser plusieurs réservations)
- Page de détail avec boutons Accepter / Refuser
- Mise à jour du statut via AJAX (sans rechargement)

**Emails automatiques** :
- Envoyés automatiquement à l'acceptation ou au refus
- 2 templates configurables (acceptation / refus) avec variables :
  - `{{client_prenom}}`, `{{client_nom}}`, `{{client_email}}`, `{{client_telephone}}`
  - `{{reservation_date}}`, `{{reservation_heure}}`, `{{reservation_personnes}}`, `{{reservation_message}}`
  - `{{restaurant_nom}}`
- Template HTML responsive (compatible email clients)
- Envoi via `wp_mail()` → capturé par Mailpit en développement

**Page de configuration** (WP Admin > Réservations > Configuration) :
- Nom et email de l'expéditeur
- Objet + corps du template email d'acceptation
- Objet + corps du template email de refus
- Bouton "Envoyer un email de test" → vérifiable sur `http://localhost:8025`

## Concepts WordPress ↔ Symfony

| WordPress | Symfony |
|---|---|
| `add_action()` / `add_filter()` | `EventDispatcher` / `EventSubscriber` |
| `functions.php` | `services.yaml` + Kernel subscribers |
| `wp_enqueue_script/style()` | `encore_entry_*_tags()` / `importmap` |
| Custom Post Type | Entity Doctrine |
| `WP_Query` | Repository / QueryBuilder |
| `get_post_meta()` | Propriété de l'Entity |
| Shortcode `[...]` | Twig Component / `render(controller(...))` |
| `wp_mail()` | Symfony Mailer |
| Nonce `wp_create_nonce()` | CSRF Token `isCsrfTokenValid()` |
| `$wpdb->get_results()` | DBAL / PDO direct |
| `get_option()` / `update_option()` | Config Bundle / `.env` |
| Customizer API | EasyAdmin / SonataAdmin forms |
| Settings API | FormType + handleRequest() + flush() |
| `WP_List_Table` | SonataAdmin / EasyAdmin list view |
| `do_action('custom_event')` | `$dispatcher->dispatch(new CustomEvent())` |
| Must-use plugin (`mu-plugins/`) | Bundle chargé dans `Kernel::registerBundles()` |
| `register_activation_hook()` | Migration Doctrine (setup initial) |

## Activation et test

```
1. Finalisez l'installation WP   →  http://localhost:8080
2. Activez le thème              →  Apparence > Thèmes > Restaurant Theme
3. Activez le plugin             →  Extensions > Restaurant Reservation > Activer
4. Personnalisez le thème        →  Apparence > Personnaliser
5. Ajoutez des plats             →  WP Admin > Carte > Ajouter un plat
6. Créez une page Réservation    →  Pages > Ajouter (contenu : [restaurant_reservation])
7. Testez une réservation        →  Frontend > remplissez le formulaire
8. Traitez la réservation        →  WP Admin > Réservations > Accepter
9. Vérifiez l'email envoyé       →  http://localhost:8025 (Mailpit)
10. Configurez les templates     →  WP Admin > Réservations > Configuration
```
